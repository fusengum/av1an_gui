# av1an_gui

[av1an](https://github.com/rust-av/Av1an) を画面で操作する、分割並列エンコードのツールです。
映像を場面ごとに細かく分け、エンコーダを CPU のコア数に合わせて何本も同時に動かします。8 コアの PC でも、128 コア以上のサーバーでも、並列数は自動で決まります。

## できること

- エンコーダ: **SVT-AV1** / aomenc / rav1e（AV1）、x265（HEVC）、x264（H.264）
- 実写・アニメ向けの設定を同梱（ファイルごとに切り替えられます。追加パラメータで上書きもできます）
- 並列数とスレッド数を、CPU 数と空きメモリから自動で決めます（上限はありません）
- 目標画質（VMAF）モード。途中で止めても続きから再開します
- 黒帯の自動切り取り、1080p への縮小
- 元の音声・字幕・チャプターはすべて引き継ぎます。音声は Opus に変換もできます
- HDR10 / HLG の色情報とマスタリング情報を引き継ぎます
- デスクトップ版（Qt）と Web 画面（ブラウザから操作。VM・サーバー向け）。キューと進捗は両方で共通です
- 終わった後のスリープ・休止状態・シャットダウン
- 画面からの更新
- Windows / Linux。**Python も入っていない状態から全自動で環境を作ります**（Linux 版は未検証です）

## 動作環境

| | |
|---|---|
| OS | Windows 10 / 11（64 ビット）、Linux（Debian / Ubuntu / Fedora 系。**未検証**） |
| CPU | AVX2 が使える CPU をおすすめします（使えないとエンコーダが大幅に遅くなります） |
| メモリ | 並列数に合わせて自動で調整します。4K の SVT-AV1 は 1 本あたり約 7 GB が目安です |
| ディスク | 作業フォルダに、入力ファイルと同じくらいの空きがあると安心です |
| ネット | インストールと更新のときに使います |

## インストール

### Windows

1. [Releases](https://github.com/fusengum/av1an_gui/releases) から ZIP をダウンロードし、好きな場所に展開します（`C:\tools\av1an_gui` など。Program Files は書き込めないので使えません）
2. `install.bat` を実行すると、画面付きのインストーラーが開きます
   - Python（uv で取得し、このフォルダ内に置きます）、ライブラリ、FFmpeg、MKVToolNix、av1an、各エンコーダを自動で取得します
   - すでに入っているものは入れ直しません。PC に Python 3.12〜3.13 があればそれを使い、FFmpeg などのツールも PATH にあればそれを使います。取り直すときは「変換ツールを取り直す」にチェックを入れます
   - 管理者権限は不要です。Web 画面のファイアウォールの許可のときだけ、確認（UAC）が 1 回出ます
   - コンソールで入れる場合は `install_cli.bat` を使います（`-NoWeb` / `-Port 9000` / `-Force`）
3. デスクトップの `av1an_gui` から起動します

### Linux（Debian / Ubuntu / Fedora 系）

> **Linux 版は、まだ実際の環境で動作を確かめていません。** インストーラー・Docker での av1an の実行・シーン検出の進み具合・更新などは、Windows 版と同じ考え方で作ってありますが、うまく動かないことがあります。不具合があれば [Issues](https://github.com/fusengum/av1an_gui/issues) で知らせてください。

```bash
./install.sh
```

| オプション | 内容 |
|---|---|
| （なし） | デスクトップ版と Web 画面 |
| `--no-gui` | 画面のないサーバー（Web 画面だけ） |
| `--no-web` | Web 画面を常駐させない |
| `--port 9000` | Web 画面のポート |
| `--nvidia` | NVIDIA GPU のドライバも入れる |
| `--force` | 外部ツールを取り直す |

- apt / dnf で MKVToolNix・Docker・Qt の依存ライブラリを入れます（sudo を使います）
- av1an とエンコーダは Docker イメージ `masterofzen/av1an:master` を使います
- Web 画面は systemd のサービスとして常駐します

### PC の環境への影響

すでに Python で開発している PC でも、その環境を変えないように作っています。

- Python・ライブラリ・uv・外部ツール・設定・ログは、すべてこのフォルダの中に置きます（`tools/`、`.venv/` など）
- VapourSynth のプラグインと、VapourSynth が使う Python の設定も、このフォルダの中（`tools/vsplugins`・`tools/vsconfig`）に置き、av1an を動かすときだけ読ませます。PC に入っている VapourSynth の設定（`%APPDATA%\vapoursynth` など）には触れません
- PC にすでにある Python・uv・FFmpeg などは、条件に合えば**使うだけで、変更しません**。PATH・利用者のフォルダ（`~/.local/bin` など）・Windows のレジストリ（`py` ランチャーの一覧）にも何も足しません
- このフォルダの外に作るもの:
  - Windows: デスクトップのショートカット、Web 画面の自動起動（ログオン時のタスク、またはスタートアップのショートカット）、ファイアウォールの規則（Web 画面のポートと、このフォルダの Python）
  - Linux: 足りない OS のパッケージ（apt / dnf。入っているものは入れ直しません）、`docker` グループへの追加、Web 画面の systemd のサービス、ファイアウォールの規則（無いときだけ足します）、ランチャー（`~/.local/share/applications`）
  - 作業フォルダ（`av1gui_<番号>`。英数字のパスが要るときは `EncodeTemp` などの中に作ります）
- アンインストールで消すのは、上のうち**このフォルダのものだけ**です。別の場所に入れた同じツールや、利用者のファイル・プロセス・ファイアウォールの規則には触れません。OS のパッケージと av1an の Docker イメージは残します（イメージは `--docker` を付けたときだけ消します）

### Proxmox などの VM で多コアを使う場合

- CPU の種類は `host` にしてください（既定の `x86-64-v2-AES` だと AVX2 が使えず、エンコーダが大幅に遅くなります）
- 2 CPU のホストでは NUMA を有効にし、ソケット数をホストに合わせてください
- Windows で論理プロセッサが 64 を超えても、エンコーダは別々のプロセスで動くため、全コアを使えます

## はじめての使い方

1. `av1an_gui` を起動します。右上が「環境 OK」になっていることを確かめます（「要セットアップ」なら、「設定」の「外部ツール」で取得します）
2. 動画ファイルかフォルダを一覧にドロップします（「ファイル追加…」「フォルダ追加…」でも追加できます）。追加したファイルはすぐキューに入り、Web 画面にも出ます
3. 一覧の各行で、種類（実写 / アニメ / 標準）・解像度・黒帯・音声を選びます。行を選んで右クリックすると、まとめて変えられます
4. 下の「エンコード」で、エンコーダ・画質・速度・保存先を選びます。迷ったら初めの値（SVT-AV1・標準・遅い）のままで大丈夫です
5. 「エンコード開始」を押します。上から順に 1 件ずつ処理します
6. 状態の欄に「シーン検出中 37%」「並列エンコード中（21 本, チャンク 12/307 完了, 残り 1:02:10）」のように進み具合が出ます。左下の「ログ」で詳しい経過を見られます

各項目の ⓘ にマウスを乗せると、説明が出ます。

## 画面と機能

### キュー（デスクトップ版と Web 画面で共通）

- キューと進捗は、この PC で動く Web サーバーが受け持ちます。デスクトップ版と Web 画面のどちらにも同じキューが出ます。どちらで追加・削除・停止しても、もう一方に反映されます
- キュー全体に「開始 / 停止」があります。どちらの画面の「エンコード開始」でも、上から順に処理し、全部終わると停止に戻ります
- 始まる前のファイルは、デスクトップ版で種類・解像度などを変えられます
- デスクトップ版を閉じても、エンコードは裏で続きます
- キューは `logs/queue.json` に保存するので、サーバーを起動し直しても残ります
- サーバーが動いていなければ、デスクトップ版を開いたときに自動で起動します

### Web 画面

- `http://<この PC の IP>:8765/` を開きます。「キュー」「設定」「環境」の 3 つの画面があります
- 「キュー」で、この PC 上のファイルを選んでキューに追加できます
- **認証はないため、LAN の中だけで使ってください**
- 他の PC から使うか・ポート・ログオン時の自動起動は、デスクトップ版の「設定」→「Web 画面」で変えます（管理者の確認などが、この PC の画面で必要なためです）
- 手動で起動するときは `web.bat`（Windows）/ `.venv/bin/python -m shared.web`（Linux）を使います。ログは `logs/web.log` です

### 設定

デスクトップ版の「設定」にタブでまとめています。Web 画面の「設定」タブにも、同じ項目が出ます。

| タブ | 内容 |
|---|---|
| 一般 | ファイル名の末尾、作業フォルダ、作業ファイルを残すか |
| 追加時の既定 | これから追加するファイルの、種類・解像度・黒帯・音声の初めの値 |
| 分割 | 分割の長さ（通常は「自動」のままで大丈夫です）、分割方法（自動: lsmash → ffms2 → hybrid）、シーン検出の方法 |
| Web 画面 | 他の PC のブラウザから使うか、ポート、自動起動 |
| 外部ツール | FFmpeg などの検出と取得、いまの版 |

エンコーダ・画質・速度・並列数・目標画質・追加パラメータ・エンコーダの場所・保存先は、メイン画面で変えます。

### 終わった後の電源操作

画面の下（Web 画面はキューの上）の「終わったら」で、スリープ・休止状態・シャットダウンを選べます。両方の画面で共通です。

- キューがすべて終わってから 60 秒後に実行します。その間は「取り消す」で止められます
- 「停止」で止めた場合や、最後のファイルを中止した場合は実行しません
- 仮想マシンでは、スリープや休止状態が使えないことがあります

### 出来上がるファイル

- 保存先（空欄なら入力と同じフォルダ）に、`元の名前_AV1.mkv`（HEVC は `_HEVC`、H.264 は `_AVC`）で書き出します。同じ名前があれば `(2)` などを付けます
- 元の音声・字幕・チャプター・添付ファイル（字幕用のフォントなど）はすべて入れます。音声を Opus に変換した場合は、変換したものを入れます（言語・タイトル・既定のフラグは残ります）
- 出来上がったファイルで、音声と字幕が欠けていないかを確かめます。MKV に入れられない形式などで入らなかったトラックがあれば、「完了（注意あり）」として、どのトラックかを知らせます
- HDR10 / HLG の色情報とマスタリング情報も MKV に書きます（HDR10+ の動的な情報は引き継がず、HDR10 として出力します）

### 途中で止める・再開する

- 「停止」を押すと、処理中のファイルは待機に戻ります。次に「エンコード開始」を押すと、終わったチャンクの続きから再開します
- 途中の分は作業フォルダの `av1gui_<番号>` に残ります。同じファイルを同じ設定でもう一度エンコードしたときも、続きから再開します。完了すると自動で消します

## 更新

- 新しい版が出ていると、デスクトップ版の見出しに「更新 x.y.z」が出ます（開いたときと、1 日 1 回確認します）。押すと新しい版を取ってきて入れ替え、終わると自動で開き直します
- Web 画面の「環境」タブからも、確認と更新ができます
- 設定（`settings*.json`）・キュー・ログ・取得した外部ツール・Python の環境は、そのまま残ります。ライブラリは `requirements.txt` が変わったときだけ入れ直します
- エンコード中は更新できません。途中で失敗したら、元の版に戻します。経過は `logs/update.log` に残ります
- Linux で `install.sh` が変わった版では、必要に応じて `sudo ./install.sh` を実行してください

## 困ったとき

| こんなとき | 確かめること |
|---|---|
| 右上が「要セットアップ」 | 「設定」→「外部ツール」の「不足ツールを自動セットアップ」で取得します |
| 進捗がしばらく動かない | 最初のチャンクが終わるまでは、出力の大きさで進み具合を見積もります。「ログ」でエンコーダが動いているかを確かめてください |
| エンコードがとても遅い | VM の場合は、CPU の種類が `host` になっているか確かめてください（AVX2） |
| 「完了（注意あり）」になった | 入らなかったトラックが状態の欄に出ます。元のファイルの、MKV に入れられない形式の字幕などです |
| デスクトップ版と Web 画面で内容が違う | 同じフォルダのサーバーは 1 つだけ動きます。古い版のサーバーが残っている場合は、デスクトップ版がエンコード中でないときに自動で起動し直します。直らないときは `install.bat` をもう一度実行してください |
| Web 画面が開けない | 「設定」→「Web 画面」で「他の PC のブラウザから使えるようにする」がオンか、ファイアウォールの許可（`web_firewall.bat`）を確かめてください |

ログの場所:

| ファイル | 内容 |
|---|---|
| 「ログ」（画面の左下） / Web 画面の各行の「ログ」 | ファイルごとのエンコードの経過 |
| `logs/web.log` | Web サーバー |
| `logs/update.log` | 更新 |

## 詳しい仕組み

### 種類ごとの設定

| エンコーダ | 実写 | アニメ |
|---|---|---|
| SVT-AV1 | `--tune 0 --enable-qm 1 --qm-min 0 --enable-variance-boost 1 --film-grain 8 --ac-bias 1.0` | `--tune 0 --enable-qm 1 --qm-min 0 --enable-variance-boost 1 --variance-boost-strength 3 --film-grain 0` |
| aomenc | `--tune-content=film --enable-qm=1` + 粒子の合成（photon noise 8） | `--enable-qm=1` |
| rav1e | 粒子の合成（photon noise 8） | — |
| x265 | `--aq-mode 3 --psy-rd 2 --psy-rdoq 1.5 --no-sao --deblock -1:-1 --no-strong-intra-smoothing --bframes 6 --rc-lookahead 40` | `--bframes 8 --psy-rd 1 --psy-rdoq 1 --aq-mode 3 --aq-strength 0.8 --deblock 1:1 --rc-lookahead 60` |
| x264 | `--tune film --aq-mode 3` | `--tune animation --aq-mode 3` |

- 「標準」は調整しません。画質（CRF など）と速度（preset など）は、エンコーダごとの尺度に変換して渡します
- SVT-AV1 は版によって使えるオプションが違うため、その版の `--help` にないオプションは自動で外します
- 派生版（SVT-AV1-PSY など）を使うときは、「エンコーダの場所」に実行ファイルを指定してください（ファイル名は標準と同じにしておいてください）
- 値は `av1gui/encoders.py` と `shared/core/tuning.py` にまとめてあります

### 並列数の決め方

「CPU 数 ÷ 1 本あたりのスレッド数」と「空きメモリ × 0.9 ÷ 1 本あたりのメモリ」の小さい方です。余ったコアは、各エンコーダのスレッドに回します。

| エンコーダ | 4K（スレッド / メモリ） | 1080p 以下 |
|---|---|---|
| SVT-AV1 | 8 / 7 GB | 4 / 2.5 GB |
| x265 | 4 / 3.5 GB | 3 / 1.5 GB |
| aomenc・rav1e | 4 / 3 GB | 3 / 1.2 GB |
| x264 | 4 / 2 GB | 3 / 0.8 GB |

例: SVT-AV1 で 4K、64 コア・空きメモリ 90 GB → 8 本 × 8 スレッド。並列数・スレッド数は手動でも指定できます。

**並列数アシスト**: メイン画面の「アシスト…」（Web 画面は「設定」→「並列数」）で、主に扱う解像度（4K / 1080p 以下 / 両方）、CPU の使い方（全部 / 1 割残す / 半分）、OS 用に残すメモリを答えると、エンコーダごと・解像度ごとに並列数 × スレッド数を決めて保存します。並列数が 0（自動）のとき、入力の横幅が 3200 以上なら 4K 用、それ未満なら 1080p 用の値を使います。優先順位は 手動 → アシスト → 自動 です。

### 分割

映像を場面の切れ目で分け、分けたもの（チャンク）を並列でエンコードします。

分割方法の「自動」は、lsmash → ffms2 → hybrid の順に使えるものを選びます。lsmash / ffms2 は索引を作って必要な場面だけを読むので、エンコードを始めるまでが速くなります（VapourSynth のプラグイン L-SMASH-Works / FFMS2 を使います。Windows ではセットアップで自動取得し、Linux の Docker イメージには同梱されています）。hybrid はプラグインが要りませんが、キーフレームを調べるための読み込みと、元のファイルと同じ大きさの切り出しが増えるため、大きなファイルや HDD では準備に何分もかかることがあります。

分割の長さの「自動」は、1 つ最大 10 秒を基本に、短い映像では分割の数が並列数の 4 倍以上になるよう短くします（下限 2 秒）。最小の長さは 1 秒分のフレーム数（24 fps なら 24 フレーム）です。「短め（最大 5 秒）」「長め（最大 20 秒）」「手動で指定」も選べます。

## コマンドライン

```
python -m av1gui check
python -m av1gui encode FILE_OR_DIR... [--encoder svt-av1|aom|rav1e|x265|x264] [--quality high|standard|small|N]
                                       [--speed slow|medium|fast] [--content film|anime|standard]
                                       [--res keep|1080p] [--crop auto|none] [--audio copy|opus]
                                       [--workers N] [--threads N] [--target-vmaf 95] [--extra "..."] [--out DIR]

```

## アンインストール

`uninstall.bat`（Windows）/ `./uninstall.sh`（Linux。`-y` で確認なし、`--docker` で av1an の Docker イメージも削除）を実行します。
アプリのフォルダ（Python・取得したツール・設定を含む）、ショートカット、Web 画面の自動起動とファイアウォールの規則、作業フォルダを消します。エンコード済みの動画は残します。

## 開発者向け

### 構成

```
VERSION        いまの版
shared/        共通部分（外部ツールの取得・解析・実行・設定画面・Web 画面・セットアップ・更新）
  core/        tools（取得と検出）/ av1an / probe / runner / video / tuning / power / config
  gui/         テーマ・設定画面（タブ・設定項目の定義から作るページ）
  web/         Web 画面（FastAPI + 静的ページ）とキュー、デスクトップ版からつなぐクライアント
  update.py    更新（GitHub のリリースから入れ替える）
  version.py   版とコードの指紋
  apps.ps1     インストーラー用のツール判定
av1gui/        av1an_gui 本体（app.json / env.py / webapp.py / settings_schema.py を持つ）
install*.ps1 / install.sh / uninstall* / web_firewall*   インストーラー類
```

`shared` は、フォルダ直下の `app.json` を持つパッケージを「ツール」として扱います。ツールは `env.py`（使う外部ツールの一覧）と `webapp.py`（Web 画面への登録）を持てば、インストーラー・設定画面・Web 画面にそのまま載ります。設定項目は `settings_sections`（見出し付きの定義）で渡すと、デスクトップ版の設定画面と Web 画面の設定タブが同じ定義から作られます。
